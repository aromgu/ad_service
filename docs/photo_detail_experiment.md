# 사진 한 장 → 세로 광고 상세페이지 실험

실험일: 2026-09-10 · 버전: `photo-detail-0.1` · 상태: **판매자 검토용 초안**

기존 `detail_visual` 단일 대표 이미지나 `/v1/mock/detail-pages` 모의 API와는
별도의 실험이다. 운영 API에는 아직 연결하지 않았다. 프론트 서비스를 만드는 작업이
아니라 **사진 분석·문구 생성 모델의 출력을 긴 페이지로 검토하는 모델 실험**이다.

## 실제 실행 범위

1. 업로드 사진과 사용자 지정 분야·대상을 GPT-5.4-mini에 전달한다.
2. 사진의 외관 관찰, 문구, 관찰 근거, 미확인 정보 목록을 구조화된 JSON으로 받는다.
3. 검증된 JSON을 고정 HTML 템플릿에 배치한다. 모델 출력은 전부 이스케이프한다.
4. 원본 사진 전체 및 CSS 확대 영역을 사용한다. 원본 이미지 바이트는 보존한다.

**새 이미지 생성, 배경 제거, 착용컷 생성은 하지 않았다.** 이미지 확대 위치와
페이지 순서는 코드의 분야별 템플릿이 정한다. 모델이 HTML이나 정확한 좌표를
생성한 실험이 아니다. 사용자 지정 사진을 기존 VM의 프로젝트 API 설정으로
호출했으며, 별도 assistant 이미지 생성 결과를 프로젝트 결과로 대체하지 않았다.

참고한 공식 API 형식: [이미지 입력](https://developers.openai.com/api/docs/guides/images-vision),
[구조화된 출력](https://developers.openai.com/api/docs/guides/structured-outputs).

## 실측 결과

| 입력 | 모델 분석·문구 시간 | 입력 토큰 | 출력 토큰 | 새 이미지 생성 |
|---|---:|---:|---:|---:|
| 의류 전체 코디 | 6.376초 | 1,622 | 551 | 0회 |
| 화장품 | 5.742초 | 1,978 | 566 | 0회 |

각각 API 1회, 자동 재시도 없음. 시간은 모델 호출부터 JSON 검증까지이며
전송·HTML 검수·전체 사용자 대기 시간을 의미하지 않는다. 청구 비용은 확정하지
않았고 `usage`를 보존했다. 두 번 모두 상태는 `needs_review`이다.

## 입력 및 결과 해석

- 의류: 사용자가 **사진 속 전체 코디**를 선택했다. 재킷·이너·쇼츠·신발의 코디를
  소개하지만 세트 판매나 신발 포함을 확정하지 않는다.
- 화장품: 패키지 외관·색상 중심. 잎을 성분으로, 라벨 문구를 검증된 효능으로
  해석하지 않는다. 브랜드 판독도 판매자 확인이 필요하다.
- 관찰 한계: 의류 `label_text_candidates`에는 실제 전사 문자열 대신 작은 라벨의
  위치 설명이 반환됐다. 공개 문구에는 사용하지 않았으나 OCR 항목 품질은 보완 대상이다.
- 광고 한계: 화장품 결과는 효능 정보가 없어서 패키지 묘사가 많다. 전환형 광고의
  완성도를 확인한 것이 아니라, **추정 사양 없이 사진만으로 페이지 초안을 만드는
  흐름**을 확인한 결과다. 표본은 분야별 한 장, 사용자 점수 평가는 아직 안 했다.
- 초안에는 판매자 확인 목록도 표시된다. 그대로 판매 페이지에 게시하는 결과가 아니다.

## 파일

로컬 결과: `../outputs/photo_detail_20260910_001/{outfit,cosmetics}/`

- `input.*`: 원본 사진 사본
- `request.json`: 프롬프트·모델·출력 스키마·원본 SHA256
- `response.json`: 실제 API 응답
- `result.json`: 검증된 모델 출력·시간·사용량
- `preview.html`: 첫 렌더링 결과
- `review.html`: 사진 확대 영역의 반응형 비율을 조정한 검수본. 모델 재호출 없음

VM 결과: `/home/cjpark/data/photo_detail_20260910_001/`. 기존 저장소, 이미지 결과,
자격증명은 덮어쓰거나 로컬로 반출하지 않았다.

## 재현

API 키가 기존 환경변수로 설정된 실행 환경에서 아래 명령을 사용한다.
키를 명령문·JSON·로그에 넣지 않는다. 출력 디렉터리가 이미 있으면 실행을 거부한다.

```bash
python scripts/photo_detail_experiment.py --image /path/photo.jpg \
  --category outfit --output /path/new-run
```

HTML만 다시 조립할 때는 비용이 발생하지 않는다. 기존 파일을 덮어쓰지 않도록 새 이름을 지정한다.

```bash
python scripts/photo_detail_experiment.py --render-only \
  --output /path/new-run --html-name review.html
```

신규 테스트 5개: 원본 보존, 모델 호출 형식, 덮어쓰기 차단, HTML 이스케이프,
미완료·잘못된 응답 중단, 지원하지 않는 입력 거부. 전체 테스트는
`PYTHONPATH=src .venv/bin/pytest -q`로 78개 통과. `ruff check .`, `git diff --check` 통과.

브라우저 기본 너비에서 두 페이지의 원본·확대 영역 로드 및 가로 넘침 없음을 확인했다.
390px 모바일 너비 설정은 브라우저에 실제 반영되지 않아 모바일 검증 완료로 보지 않는다.
전체 페이지 스크린샷은 캡처 도구의 타일 중복으로 제외했으며, 구간별 화면으로 검수했다.
결과물은 외부 이미지 서버 없이 열리는 HTML이다. 긴 PNG 내보내기는 아직 구현하지 않았다.

후속 작업은 판매자 확인 정보 수집과 이미지 연출컷 추가 여부를 분리해서 비교하고,
검증한 구조를 기존 상세페이지 계약에 매핑하는 것이다.
